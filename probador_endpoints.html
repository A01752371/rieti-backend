Sistema

GET /health ›

Verifica que la función responde y que sus variables de entorno están configuradas. No toca la base de datos.

Catálogos

GET /api/v1/catalogos/actividades ›

Lista de actividades laborales para el selector del formulario de reporte.

GET /api/v1/municipios ›

Municipios adheridos a la red RIETI. Los no adheridos no aparecen.

Reportes ciudadanos

POST /api/v1/reportes ›

Registra un reporte y devuelve el folio generado con las siglas del municipio.

Si eliges fotos, se suben solas después de crear el reporte.
GET /api/v1/reportes/:folio ›

Consulta ciudadana del estatus. No requiere sesión y solo devuelve campos públicos.

Evidencias

FLUJO Subir una foto a S3 (3 pasos) ›

Pide la URL firmada, sube el archivo directo a S3 con PUT y registra la evidencia en la base.

1 Solicitar URL firmada
2 Subir el archivo a S3 (PUT)
3 Confirmar la evidencia
POST /api/v1/evidencias/confirmar ›

Registra en la base una evidencia ya subida. La purga se programa a 10 días.

POST /api/v1/evidencias/url-lectura token ›

Genera una URL firmada para ver una foto del bucket privado. Dura 5 minutos.

Si la genera, la imagen se muestra aquí abajo.

Autenticación

POST /api/v1/auth/login ›

El token que regrese se guarda solo y se manda como Authorization: Bearer en las rutas protegidas.

GET /api/v1/auth/me token ›

Devuelve el contenido del token de la sesión actual.

POST /api/v1/auth/password token ›

Cualquier usuario con sesión cambia su propia contraseña. Debe comprobar que sabe la actual.

Mínimo 8 caracteres y distinta de la actual.

Gestión de usuarios

POST /api/v1/admin/usuarios solo Administrador ›

Alta de una cuenta de funcionario. La contraseña se guarda como hash de bcrypt.

GET /api/v1/admin/usuarios solo Administrador ›

Consulta de cuentas con filtro por municipio. El hash nunca viaja en la respuesta.

Panel administrativo

GET /api/v1/admin/reportes token ›

Bandeja de reportes. Un Alimentador solo ve los de su municipio; un Administrador ve todos.

GET /api/v1/admin/reportes/:folio/expediente token ›

Expediente completo: datos del reporte, evidencias, bitácora e historial de estatus.

POST /api/v1/admin/atencion token ›

Registra una actuación en bitácora. Si se manda un estatus nuevo, la justificación es obligatoria.

POST /api/v1/admin/transferencias solo Administrador ›

Transferencia entre municipios, canalización a la PPNNA o descarte del reporte.

Casos de error

PRUEBAS Validaciones que deben fallar ›

Comprueba que el backend rechaza lo que debe rechazar. Cada botón debe devolver 400, 401, 403 o 404.
